## 🎯 What Is This?

The `.framework/` folder is a **production-ready, universal development system** that contains:

- **Planning methodologies** - How to structure and plan any feature or project
- **AI agents** - Specialized assistants for specific tasks
- **Code standards** - Industry best practices for quality code
- **Templates** - Starter code and planning documents
- **Integration guides** - Quick setup for common services
- **Utilities** - Helper functions, hooks, scripts, automation
- **Documentation** - Everything explained and referenced

**Source**: Battle-tested from 2 production projects (Stayflo + Lostmonster)

**Purpose**: Copy this folder to any new project and instantly have professional development infrastructure

## 🚀 Quick Start (5 Minutes)

### Step 1: Copy the Framework

```bash
# Copy to your new project
cp -r /path/to/.framework /path/to/new-project/.framework

# Example:
cp -r /Users/james/Projects/twin/.framework /Users/james/Projects/wildtrax/.framework
```

### Step 2: Read the Documentation

**In order**:
1. This file (HOW-TO-USE.md) ← You're reading it
2. `COMPLETE-SETUP-GUIDE.md` ← Complete reference
3. `.ai/README.md` ← AI framework details

**Time**: 30 minutes

### Step 3: Customize 6 Files (2-3 hours)

Only these files need project-specific customization:

1. **CLAUDE.md** - Update project name and context
2. **PRD-TEMPLATE.md** - Copy to `PRD.md`, add your product details
3. **PRO-TEMPLATE.md** - Copy to `PRO.md`, add your roadmap
4. **.ai/project/PROJECT.md** - Update tech stack and patterns
5. **.ai/project/DESIGN-LANGUAGE.md** - Update brand identity
6. **.ai/project/DOMAIN-KNOWLEDGE.md** - Update business domain

**Time**: 2-3 hours total

### Step 4: Start Building!

Everything else (72 files) works as-is for any project. ✅

## 💡 Common Workflows

```
1. Read: .ai/frameworks/coda.md
2. Use: .ai/templates/feature-planning.md
3. Apply: CODA framework (Context-Objective-Details-Acceptance)
4. Optional: Invoke feature-builder agent
5. Create: PLANX execution blueprint
6. Build: Following the plan
```

---

### Building a UI Component

```
1. Read: .ai/templates/component-planning.md
2. Apply: .ai/frameworks/design-variations.md (create 5 options)
3. Get feedback: User selects preferred version

5. Optional: Invoke ui-builder agent

7. Audit: Use PIXELX for quality scoring
```

### Decision Trees

#### Which Framework Should I Use?

```
Is it a complex feature?
├─ Yes → Use CODA + PLANX
└─ No → Simple implementation

Is it UI/UX work?
├─ Yes → Use Design Variations + PIXELX
└─ No → Skip design frameworks

Is it a CRUD feature?
├─ Yes → Use CRUDX
└─ No → Use CODA

Is it marketing content?
├─ Yes → Use AIDA + industry messaging
└─ No → Skip content frameworks

Need quality audit?
├─ UI/UX → PIXELX
├─ Design → SOPHIA
└─ Code → code-reviewer agent

Still unsure?
→ Read: .ai/frameworks/FRAMEWORK-MAP.md
```

---

#### Which Agent Should I Use?

```
Content generation needed?
→ handbook-generator agent

UI component needed?
→ ui-builder agent

Code review needed?
→ code-reviewer agent

Full feature needed?
→ feature-builder agent

Complex task spanning multiple areas?
→ Use multiple agents sequentially
```

## ⚡ Power User Tips

### 1. Git Automation
Enable git hooks for automatic changelog generation and commit standards:
```bash
cd utilities/scripts/git-automation
./install-git-hooks.sh
```

### 2. Quality Scoring
Use PIXELX and SOPHIA for objective quality scores (0-100) instead of subjective reviews.

### 3. Agent Combinations
Combine agents for complex tasks:
- `feature-builder` + `ui-builder` = Complete feature with UI
- `handbook-generator` + `code-reviewer` = Content with quality check

### 4. Framework Stacking
Stack frameworks for comprehensive planning:
- CODA (overall plan) + PLANX (execution) + PIXELX (quality audit)

### 5. Standards Enforcement
Use `.ai/standards/` as team onboarding and code review checklists.

## 🚨 Common Mistakes to Avoid

### ❌ Don't Skip Planning
- **Mistake**: Jump straight to coding
- **Fix**: Use CODA for complex features, component-planning for UI

### ❌ Don't Ignore Standards
- **Mistake**: "I'll refactor later"
- **Fix**: Follow standards from the start, use code-reviewer agent

### ❌ Don't Forget to Customize
- **Mistake**: Use Stayflo references in your project
- **Fix**: Update the 6 project-specific files

### ❌ Don't Use Wrong Framework
- **Mistake**: Use CRUDX for non-database features
- **Fix**: Check FRAMEWORK-MAP.md for guidance

### ❌ Don't Work in Isolation
- **Mistake**: Not using agents when they could help
- **Fix**: Invoke agents for specialized tasks
