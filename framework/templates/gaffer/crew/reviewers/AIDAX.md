## What is AIDA?

**A**ttention -> **I**nterest -> **D**esire -> **A**ction

A marketing framework for structuring content to guide users from discovery to conversion.

## AIDA for [entity-primary]

### A - ATTENTION
*"Make the [entity-primary] stand out immediately"*

**Purpose:** Hook potential users in 3 seconds

**Elements:**
- Hero photo/visual (professional quality)
- Clear primary data display (key metric — NEVER hidden)
- Key stats visible (primary attributes at a glance)
- Freshness indicator (days since confirmed)
- Type/category badge

**[PROJECT] Implementation:**
```
+-------------------------------------+
| [Hero Visual - Full Width]          |
|                                     |
| [Primary Metric]      [Type Badge] |
| [Location/Category]                |
| [Key Stat] . [Key Stat] . [Stat]   |
| Confirmed X days ago               |
+-------------------------------------+
```

**Best Practices:**
- Professional, bright hero visual (not dark/blurry)
- Primary metric prominent and exact (no vague ranges)
- Category/location clear
- Freshness signal visible
- Don't bury the primary metric
- Don't use generic stock imagery
- Don't omit key specs

### I - INTEREST
*"Build interest with context"*

**Purpose:** Keep potential users engaged with valuable information

**Elements:**
- Detailed features/attributes list
- Location/category context
- What makes this [entity-primary] special
- [PROJECT-DOMAIN] context (for unfamiliar users)

**[PROJECT] Implementation:**
```
## Features
- [Feature 1 with context]
- [Feature 2 with context]
- [Feature 3 with context]

## Location / Context
- [Contextual detail 1]
- [Contextual detail 2]
- [Contextual detail 3]

## Why [PROJECT-DOMAIN]?
[Paragraph explaining the domain/area value proposition
for users who may be unfamiliar.]
```

**Best Practices:**
- Lead with what users care about most
- Provide context (not just raw data)
- Explain the [PROJECT-DOMAIN] value for newcomers
- Highlight unique differentiators
- Don't just list features without context
- Don't assume user knowledge of the domain
- Don't hide negative aspects (be honest)

### D - DESIRE
*"Create desire through lifestyle/value vision"*

**Purpose:** Make viewers imagine themselves using/owning/experiencing

**Elements:**
- Lifestyle/value-focused description
- High-quality visual gallery
- Trust signals (verified [entity-tertiary], credentials)
- Social proof (if applicable)
- Area/category highlights

**[PROJECT] Implementation:**
```
## Imagine [Outcome]
[Lifestyle/value-oriented description painting a picture
of what the user's experience would be like.]

## Trust Signals
+-- Listed by: [Entity] (Verified)
+-- Responds within X hours on average
+-- Data confirmed X days ago
+-- [Social proof metric]

## Visual Gallery
[High-quality images showing experience, not just specs]
```

**Best Practices:**
- Paint a lifestyle/value picture, not just specs
- Show trust signals for [entity-tertiary]
- Include visuals of the experience, not just the product
- Don't oversell (be honest about limitations)
- Don't use generic descriptions
- Don't skip trust signals

*"Make conversion effortless"*

**Purpose:** Convert interest into [entity-secondary] with zero friction

**Elements:**
- Prominent conversion form (minimal fields)
- Contact info visible
- Multiple contact options
- Clear next steps
- No account required (friction = death)

**[PROJECT] Implementation:**
```
+-------------------------------------+
```

**Best Practices:**
- Minimal form fields (reduce friction)
- No account/signup required
- Alternative contact methods visible
- Set expectations (response time)
- Reassure commitment-phobes
- Don't hide the conversion form
- Don't require phone number
- Don't make them guess what happens next

## AIDAX Scoring System

**Score each section: 0-25 points per letter**
**Total: 0-100 points**
**Target: 80+ for high-converting pages**

### Brand Alignment Gate (Pre-Scoring Qualifier)

**Before scoring, the page must pass brand alignment. If it fails, the AIDA score is invalid** — you can't measure conversion of something that doesn't look like the product.

**Brand Alignment:** Does the page feel like [PROJECT]? Match the project's visual identity, not a generic template. [BRAND-BG] backgrounds, white elevated cards, [BRAND-PRIMARY] CTAs. If it could belong to any generic website, it fails brand alignment.

**Provenance Rule:** Before scoring, verify the page passes the Provenance Rule from the AI Slop Test — every visual element must exist on another [PROJECT] page. If a hero section, card treatment, or layout pattern appears nowhere else on the site, it's orphaned and unscored until resolved.

If brand alignment fails, stop. Fix the visual identity first, then re-run AIDAX.

## Checkpoint Mode (INSPX Integration)

When invoked by INSPX during the automated inspection pipeline, AIDAX operates in **Checkpoint Mode** — same AIDA dimensions, same scoring, structured output format.

**What AIDAX receives:**
- Screenshot from Playwright (specific viewport)
- Checkpoint metadata (page name, URL, viewport, focus area)
- Feature context (what was built/changed)

**What AIDAX returns:**

```
AIDAX CHECKPOINT: [Checkpoint Name] ([viewport])
  Attention: X/25  [key observations]
  Interest:  X/25  [key observations]
  Desire:    X/25  [key observations]
  Action:    X/25  [key observations]
  TOTAL: XX/100
  Brand Alignment: PASS | FAIL [reason]
  CRITICAL: [none | list of critical issues]
```

**CRITICAL flag rules:**
- Total score below 60/100 -> CRITICAL (Major restructure needed)
- Brand Alignment fails -> CRITICAL (fix visual identity first)
- Conversion form not visible or broken -> CRITICAL
- Primary metric hidden or missing -> CRITICAL (for [Page Type A] pages)

**Non-CRITICAL issues** are logged with severity and recommendations, pipeline continues.
