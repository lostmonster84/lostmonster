# Design Systems

> Documented component libraries, design tokens, and quality standards that make every future build faster, cheaper, and more consistent.

---

## The Problem

Every new page looks slightly different from the last one. Your buttons have three different styles. Your spacing is inconsistent. Your developers argue about font sizes. Every feature takes longer because someone has to make design decisions that should've been made once.

Without a design system, you're paying for the same decisions over and over again. Inconsistency creeps in. Quality varies. Development slows down.

## What I Build

Complete design systems — not just a style guide PDF that nobody reads, but living documentation with reusable components, design tokens, and quality enforcement that your team actually uses.

### Design Tokens
Colours, typography, spacing, shadows, border radii — all defined once, referenced everywhere. Change a token, and every component updates. Dark mode support built in. Responsive breakpoints standardised.

### Component Library
Buttons, cards, inputs, modals, badges, tables, navigation — every common UI pattern built once, documented, and reusable. Each component is accessible (WCAG AA), responsive, and tested. Copy-paste ready.

### Page Patterns
Beyond individual components — complete page layouts and section patterns. Hero sections, feature grids, pricing tables, metric dashboards, form wizards. Consistent structure across every page.

### Quality Standards
Documented quality checklist with scoring. Every page and component must hit 80/100 before it ships. Categories: brand adherence, technical quality, voice and messaging, business goals, responsive UX.

### Living Documentation
Not a static PDF — a living reference page (like `/design`) that renders actual components with their code. Your team sees exactly what each element looks like and how to use it. Always up to date because it reads from the same tokens your app uses.
