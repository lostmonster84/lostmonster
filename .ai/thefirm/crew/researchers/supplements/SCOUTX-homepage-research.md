## 2. PATTERNS (What the Best All Do)

### Pattern 1: Quantified Social Proof, Not Logo Soup
**Description:** The best homepages pair customer logos with specific, measurable outcomes. Logos alone are table stakes -- the winners attach numbers.
**Examples:** Stripe ("$1.9T processed"), Vercel ("95% reduction in page load times"), Retool ("$6M saved" -- DoorDash), Webflow ("32 global sites launched in 10 days" -- Verifone), Loom ("400,000 companies")
**How to apply:** Every social proof section needs at least one quantified claim. If you have logos, pair them with a metric bar. If you have testimonials, ensure they contain specific numbers, not just praise.

### Pattern 2: Hero Headline Under 8 Words
**Description:** Top-performing heroes use punchy, benefit-driven headlines. The best are 3-6 words. Subheadlines carry the explanatory weight.
**Examples:** Notion ("One workspace. Zero busywork." -- 4 words), Raycast ("Your shortcut to everything." -- 4 words), Railway ("Ship software peacefully" -- 3 words), Pitch ("Don't just present. Pitch." -- 4 words), Loom ("One video is worth a thousand words" -- 8 words)
**How to apply:** Headline = emotional hook or outcome. Subheadline = what the product actually does. Never explain the product in the headline.

### Pattern 3: Dual CTA in Hero (Primary + Secondary)
**Description:** Nearly every studied homepage uses two CTAs in the hero: a low-friction primary ("Start for free", "Get started") and a higher-intent secondary ("Get a demo", "Contact sales").
**Examples:** Vercel ("Start Deploying" + "Get a Demo"), Stripe ("Get started" + "Sign up with Google"), Notion ("Get Notion free" + "Request a demo"), Framer ("Start for free" + "Start with AI"), Retool ("Start for free" + "Book a demo")
**How to apply:** Primary CTA = self-serve path. Secondary CTA = sales-assisted path. Primary should be visually dominant. Never use more than 2 CTAs in the hero.

### Pattern 4: Section-by-Audience Architecture
**Description:** Complex products organize their homepage by who the visitor is, not by what the product does. Visitors self-select into their path.
**Examples:** Webflow (marketers / creatives / engineers / agencies), Retool (AI teams / data teams / ops teams / support teams), Vercel (AI apps / web apps / ecommerce / marketing / platforms), Pitch (business owner / designer / sales / marketer)
**How to apply:** If the product serves multiple personas, create tabbed or segmented sections. Each persona section should have its own headline, features, and CTA. Use tabs, not separate pages.

### Pattern 5: Social Proof Immediately After Hero
**Description:** The strongest homepages place their trust signal within the first scroll -- directly below the hero, before any feature content.
**Examples:** Vercel (logo bar + metrics), Stripe (logo carousel in hero), Notion ("Trusted by top teams" logo row), Descript (16 logos in hero section), Clerk (logo carousel), Railway (12 enterprise logos)
**How to apply:** Logo bar or trust statement should be the very first section after the hero. No exceptions. This earns permission to keep scrolling.

### Pattern 6: Progressive Feature Disclosure
**Description:** Features are never dumped in a single list. They unfold from broad categories to specific capabilities as the user scrolls.
**Examples:** Loom (overview -> feature rows -> use case cards -> deep-dive sections), Stripe (solution grid -> enterprise case studies -> developer infrastructure), Raycast (extensions showcase -> AI section -> automation features -> feature gallery), Clerk (components -> auth features -> B2B -> billing -> frameworks)
**How to apply:** Structure as: Overview cards (3-4 broad capabilities) -> Detailed sections (one per capability) -> Feature grid (everything else). Each layer increases specificity.

### Pattern 7: Repeating CTA at Regular Intervals
**Description:** CTAs are not confined to hero and footer. The best pages place conversion opportunities every 2-3 sections.
**Examples:** Loom (6+ "Get Loom for free" instances), Cal.com (18+ CTAs across 11 sections), Retool ("Start for free" appears in nav, hero, mid-page, and footer), Stripe ("Start now" recurs through 13 sections)
**How to apply:** Place a CTA every 2-3 sections. The copy can vary slightly but should maintain the same primary action. Footer CTA section should mirror the hero CTA.

### Pattern 8: Interactive Product Demonstrations
**Description:** Static screenshots are being replaced by interactive demos, tabbed previews, and animated walkthroughs that show the product working.
**Examples:** Superhuman (simulated conversation flow), Clerk (component preview mockups), Vercel (code snippets + live model rankings), Raycast (tabbed extension interface with categories), PlanetScale (ASCII architecture diagrams)
**How to apply:** At minimum, show the actual product UI. Better: make it interactive or animated. Best: let the visitor try a simplified version inline. For developer tools, code snippets and terminal output are valid "demos."

### Pattern 9: Closing CTA Section Mirrors Hero
**Description:** The final section before the footer restates the core value proposition and repeats the hero CTAs. It catches scrollers who made it to the bottom.
**Examples:** Vercel ("Talk to an Expert" + "Get an Enterprise Trial"), Framer ("Design bold. Launch fast." + "Start for free"), Railway ("A better future is now boarding" + "All Aboard"), Stripe ("Ready to get started?" + "Start now" / "Contact sales"), Raycast ("Take the short way." + "Download for Mac")
**How to apply:** Final CTA section needs: a new headline (not copy-pasted from hero), the same CTA buttons as the hero, and minimal surrounding content. This is not the footer -- it is a dedicated conversion section above the footer.

### Pattern 10: Competitor Displacement, Not Comparison
**Description:** The best homepages acknowledge competitors indirectly -- by showing what they replace, not by naming comparison tables.
**Examples:** Railway (each feature lists alternatives: "Docker, Helm, Heroku, DigitalOcean"), Notion (productivity calculator showing 10 tools it replaces with cost savings), Cal.com (testimonials explicitly reference switching from Calendly), PlanetScale (latency graphs comparing to Aurora/Cloud SQL without landing page-style comparison tables)
**How to apply:** Never build comparison tables on the homepage. Instead, show the cost/complexity of the alternatives, or let testimonials mention the switch naturally.

## 3. ANTI-PATTERNS

### Anti-Pattern 1: Feature Dumping
**What it is:** Listing every feature in a flat grid or bulleted list with no hierarchy.
**Why it fails:** Users get overwhelmed and cannot identify what matters to them. No feature stands out when all features are equal.
**Who does it wrong:** Webflow (20 sections creates fatigue; many persona sections repeat similar features), Loom (15 sections with multiple overlapping feature presentations).
**Fix:** Cap at 8-12 sections. Use progressive disclosure. Lead with 3-4 hero features, then expand.

### Anti-Pattern 2: Vague Hero Headlines
**What it is:** Headlines that describe the category, not the benefit. "The modern [category] platform" tells you nothing.
**Why it fails:** Users decide in 3-5 seconds. Generic headlines waste this window.
**Evidence:** Retool's "Generate internal software better with AI" is weaker than Railway's "Ship software peacefully" because it explains the mechanism rather than the outcome.
**Fix:** Headline = outcome or feeling. Subheadline = mechanism. Never lead with "how" -- lead with "what you get."

### Anti-Pattern 3: Social Proof at the Bottom
**What it is:** Burying testimonials and logos in the lower half of the page.
**Why it fails:** 42% of visitors never scroll past the hero CTA (per SaaS conversion research). Social proof at the bottom reaches only the most engaged visitors.
**Fix:** Logos immediately after hero. Testimonials in the middle third. Case study metrics near the bottom for closers.

### Anti-Pattern 4: Single CTA Path
**What it is:** Only offering "Sign up" or only offering "Book a demo" -- not both.
**Why it fails:** Self-serve visitors will not book a demo. Enterprise visitors will not sign up for a free trial. You lose one segment entirely.
**Evidence:** Every top-performing homepage studied uses dual CTAs. Cal.com even offers "Sign up with Google" as a third, ultra-low-friction option.
**Fix:** Always offer primary (self-serve) + secondary (sales-assisted) paths. Let the visitor choose their commitment level.

### Anti-Pattern 5: Heavy Animation in the Hero
**What it is:** Complex 3D renders, video backgrounds, or JavaScript-driven animations that delay LCP.
**Why it fails:** CSS transitions during page load cause measurable LCP delay. A 70ms transition overhead pushes mobile LCP past the 2.5s threshold. Users bounce at 6-second load times.
**Evidence:** Linear's homepage is heavily JS-rendered, making content extraction difficult even for crawlers. This signals potential SEO and performance issues.
**Fix:** Use CSS transform/opacity animations only (GPU-accelerated). Defer non-critical animations. Hero visuals should be static or lightweight SVG. Move heavy 3D/video below the fold.

### Anti-Pattern 6: No Clear Audience Signal
**What it is:** A homepage that tries to speak to everyone simultaneously without persona segmentation.
**Why it fails:** A developer and a marketing director have completely different needs. Generic messaging resonates with neither.
**Fix:** Either segment by persona (Webflow's approach) or be crystal clear about who you serve in the hero subheadline. PlanetScale succeeds here by clearly targeting technical infrastructure teams with ASCII diagrams and latency benchmarks.

## 5. MOBILE PATTERNS

### Layout Adaptations at 390px
Based on observed patterns across studied sites:

1. **Hero stacks vertically.** Headline -> subheadline -> CTA(s) -> visual. The visual often shrinks or disappears entirely on mobile.
2. **Dual CTAs become stacked buttons.** Primary on top (full-width), secondary below. Some sites (Raycast) make the secondary a text link on mobile.
3. **Tab interfaces become horizontal scrollers or accordions.** Vercel's 5-tab use case section and Webflow's persona tabs both collapse.
4. **Logo bars wrap to 2 rows or become a horizontal scroll carousel.** Never a grid that forces 4+ rows of tiny logos.
5. **Feature cards go single-column.** Bento grids and 3-column layouts collapse to full-width stacked cards.
6. **Sticky mobile CTA appears.** Cal.com and Loom both show a persistent bottom CTA bar on mobile. This alone drove an 18% trial start increase in one SaaS case study.
7. **Navigation becomes hamburger menu.** All 16 studied sites use a hamburger or bottom sheet on mobile. Vercel uses a slide-out panel.
8. **Testimonial carousels become swipeable.** Single testimonial visible at a time with dot indicators.

### Mobile-Specific Metrics
- 60-75% of demos start on mobile (SaaS industry data)
- 59.7% of global web traffic is mobile (2025)
- Google uses mobile-first indexing since October 2023
- Touch targets must be minimum 44x44px (WCAG 2.5.5)

## 6. ACCESSIBILITY PATTERNS

### Homepage-Specific a11y (Beyond Generic WCAG)

1. **Hero heading must be h1.** Screen reader users navigate by heading level. The hero headline must be the single h1 on the page. All section headings below should be h2, subsections h3.

2. **Logo bars need accessible labels.** A row of customer logos without alt text is invisible to screen readers. Each logo image needs `alt="Company Name logo"`. The section needs an aria-label like "Trusted by these companies."

3. **Background video/animation in hero.** Must include `prefers-reduced-motion` media query. Users who disable motion should see a static image or no animation. Raycast's 3D cube and Vercel's runway animation must respect this.

4. **Color contrast on gradient backgrounds.** Hero sections with gradient backgrounds often fail WCAG AA contrast (4.5:1 for normal text, 3:1 for large text). Test contrast at the lightest point of the gradient, not the darkest.

5. **CTA buttons vs links.** "Start for free" should be a `<button>` or `<a>` with clear role. "Learn more" links need context -- `aria-label="Learn more about feature name"` to distinguish them for screen readers.

6. **Carousel/testimonial accessibility.** Carousels must be keyboard-navigable, announce slide changes to screen readers, and provide pause controls. Auto-rotating carousels should stop on focus/hover.

7. **Skip navigation link.** Homepage is often the longest page. A "Skip to main content" link is essential -- Figma and Clerk both implement this.

8. **Form inputs in hero.** Cal.com's "Sign up with Google" and "Sign up with email" inputs in the hero need proper labels, not just placeholder text.

## 7. PERFORMANCE PATTERNS

### LCP Optimization
- **Target:** < 2.5s on mobile, < 1.8s on desktop
- **Hero image strategy:** Use `<img>` with `fetchpriority="high"` and `loading="eager"` for the hero visual. Never lazy-load above-fold content.
- **Font loading:** Use `font-display: swap` or `font-display: optional`. Vercel uses its own Geist font with aggressive preloading. System fonts (Stripe) are the fastest option.
- **Critical CSS:** Inline above-fold CSS. Defer below-fold stylesheets. This is standard in Next.js but must be verified.

### Animation Budget
- **GPU-safe properties only:** `transform`, `opacity`. Never animate `width`, `height`, `top`, `left`, `margin`.
- **Hero animation overhead:** Keep under 70ms to avoid LCP impact.
- **Defer non-critical animation:** Below-fold animations should use `IntersectionObserver` to trigger on scroll-into-view, not on page load.
- **`prefers-reduced-motion`:** Wrap all animations in a reduced-motion media query. This also eliminates the performance cost for users who disable motion.
- **Lottie/SVG over GIF/video:** JSON-based Lottie animations and SVG animations are dramatically lighter than GIF or video backgrounds. Raycast's 3D cube is an exception justified by brand identity.

### Image Strategy
- **Format:** WebP or AVIF with JPEG/PNG fallback. Next.js Image component handles this automatically.
- **Hero image:** Max 200KB compressed. Use responsive `srcset` for mobile (390px) vs desktop (1440px).
- **Logo bars:** SVG only. Never use raster images for logos -- they look blurry at any scale and add unnecessary weight.
- **Below-fold images:** `loading="lazy"` on everything below the hero.

### Page Weight Targets
| Asset Type | Budget |
|-----------|--------|
| Total page weight | < 2MB (ideal), < 3MB (acceptable) |
| HTML | < 100KB |
| CSS | < 150KB |
| JavaScript | < 500KB (compressed) |
| Images (total) | < 1MB |
| Fonts | < 200KB (2-3 weights max) |
| Hero image | < 200KB |

## 8. PLANNING IMPLICATIONS

### What CODAX (Planner) Needs to Know Before Scoping a Homepage Build

1. **Section count drives timeline.** An 8-section homepage takes 2-3 days to build well. A 15-section homepage takes 5-7 days. A 20-section Webflow-style page takes 10+ days. Scope sections first, then estimate.

2. **Hero is 30% of the effort.** The hero section (headline, subheadline, CTAs, visual, animation, social proof bar) takes disproportionate time because it sets the design system for the entire page. Build and approve the hero before anything else.

3. **Mobile is not an afterthought.** With 60%+ traffic on mobile, the mobile layout should be designed alongside desktop, not retrofitted. Plan for touch targets, stacked layouts, and sticky CTAs from the start.

4. **Content blocks the build.** Headlines, subheadlines, CTA copy, testimonials, and social proof data must exist before development starts. Placeholder content leads to layout breakage when real content arrives. WORDX should deliver copy before DEMX starts building.

5. **Animation scope must be defined upfront.** "Add some animations" is not a spec. Define: which sections animate, what triggers them (scroll, load, hover), and whether they respect `prefers-reduced-motion`. Budget 1-2 days for animation alone on a standard homepage.

6. **Performance testing is a gate, not a nice-to-have.** Run Lighthouse before merge. LCP > 2.5s, CLS > 0.1, or INP > 200ms should block deployment. These are measurable thresholds, not opinions.

7. **Social proof is a dependency.** Logos need permission. Testimonials need approval. Metrics need verification. Start collecting these in week 1 of any homepage project -- they are often the last thing received and the first thing needed.

8. **Section order follows a proven sequence.** Based on all 16 studied sites, the winning order is:
   - Nav
   - Hero (headline + subhead + dual CTA + visual)
   - Social proof bar (logos + optional metrics)
   - Product overview / use cases (3-4 cards or tabs)
   - Feature deep-dives (2-4 sections, progressive detail)
   - Testimonials / case studies (with metrics)
   - Secondary features or integrations
   - Closing CTA section (mirrors hero)
   - Footer

9. **Breakpoints to design for.** Based on current device landscape:
   - 390px (iPhone 14/15 -- primary mobile)
   - 768px (iPad portrait)
   - 1024px (iPad landscape / small laptop)
   - 1280px (standard laptop)
   - 1440px (design target -- most sites cap content width here)
   - 1920px (large desktop -- Figma extends to 1680px content width)

10. **Navigation patterns.** All 16 studied sites use:
    - 5-7 top-level nav items max
    - Dropdown/mega-menu for complex product suites
    - 2 CTAs in nav: "Log in" (text) + "Get started" (button)
    - Hamburger on mobile (no exceptions observed)

## 9. WORKER-SPECIFIC TAKEAWAYS

### For DEMX (Builder / Layout)
- Default section structure: hero + social proof bar + 3-4 feature sections + testimonials + closing CTA = 8-10 sections
- Hero height: 80-100vh desktop, content-driven on mobile
- Content width: 1440px max with 24-32px gutters
- Use CSS Grid for bento/card layouts, Flexbox for nav and hero
- Tab components are the most common feature presentation pattern (Vercel, Raycast, Webflow, Pitch, Clerk)

### For AIDAX (Conversion Reviewer)
- Dual CTAs in hero: mandatory
- CTA every 2-3 sections: mandatory
- Social proof immediately after hero: mandatory
- Closing CTA section above footer: mandatory
- Sticky mobile CTA: strongly recommended (18% uplift evidence)
- Every testimonial should contain a specific metric or outcome

### For SOFAX (Design Quality Reviewer)
- Whitespace is a premium signal: Vercel uses 96-128px vertical section padding
- Dark mode is dominant for developer tools (Vercel, Raycast, Railway, PlanetScale, Clerk)
- Light mode is dominant for broader audiences (Notion, Loom, Cal.com, Pitch)
- Logo bars must use SVG, same visual weight, desaturated/monochrome treatment
- Max 2-3 font weights per page. System fonts or a single custom family.
- Animation must respect `prefers-reduced-motion`

### For WORDX (Copy Specialist)
- Hero headline: 3-8 words, outcome-focused, no jargon
- Hero subheadline: 15-30 words, explains what the product does
- CTA copy: action verb + benefit ("Start for free", "Deploy now", "Get started")
- Avoid: "Learn more" without context. Use "Explore [feature name]" instead.
- Testimonials work best when they mention the switch from a competitor or cite a specific number
- Section headlines should be scannable -- a user who reads only headings should understand the full value proposition

### For CODAX (Planner)
- See Section 8 above for full planning implications
- Minimum viable homepage: hero + social proof + 3 features + testimonials + closing CTA = 6 sections
- Standard homepage: 8-12 sections, 3-5 day build
- Complex homepage: 15+ sections, 7-10 day build
- Content and social proof are the critical path, not code
